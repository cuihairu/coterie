**现状**:适配器、分支测试、compose 渠道变量透传均已就绪(见 todo.md:12-13、todo.md:20)。
唯一卡点:无真实 Stripe 凭据。仓内仅测试夹具与 `.env.example` 占位,所需输入为
`sk_test_*` / `whsec_*`(或生产密钥)。

### 推荐决策
**暂缓** — 等用户提供 Stripe 真实凭据。代码面无待补实现,拿到凭据即可接线验收。

### 理由
- **成本**:继续"做"只能重复已有工作——适配器与分支测试已齐,再写任何实现都是无边际收益的重复劳动。
- **收益**:凭据到位后可立即做端到端支付验收(真实 `sk_` + `whsec_` 握手);在此之前无增量可交付。
- **风险(假绿)**:用测试夹具跑通的测试**无法证明**生产凭据下的真实支付行为——夹具里没有 Stripe 侧的真实签名与回调,强行验收会制造"看起来能跑、上线才炸"的假绿。
- **风险(安全)**:真实密钥是高价值凭据,不应由任何 agent 代为生成、申请或硬编码;凭据类事项按授权口径明确不代决。

### 立即执行动作
无。此项需用户输入 `sk_test_*` / `whsec_*`(或生产密钥),到位前不做任何硬做。

### 明确不做 / 延后什么
- 不引入 Stripe 模拟服务器(mock 端点)当验收——那只验证适配器形状,不验证真实支付语义。
- 不写占位代码、不 bump 版本、不打 tag。
- 不在 `.env.example` 之外落任何真实密钥进仓(密钥进仓即泄露面)。
